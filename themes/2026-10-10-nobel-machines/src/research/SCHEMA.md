# 研究底稿的共同约定（四个研究代理都要读）

今天是 2026-10-08。你在为「一周一题」第 4 题《把预言造出来：诺贝尔物理学奖背后的十二座装置》做研究。
读者是工程师出身的站长天杰和普通读者。页面是中文长页：十二张装置卡 + 工程思维区块 + 候补席 + 展望路线图。
你的产出是一份 **JSON 文件**（路径见各自的任务说明），由编辑（主会话）合并成页面内容。你不做页面、不碰仓库。

完整的题目规格是当周的「本周指定」（研究时另发，不在仓库里）。先把它读一遍。里面每座装置都有「种子事实」：
没标「待核」的，10/8 已对照官方页或维基粗核过；标「待核」的是凭记忆写的。你的任务是把它们核实、补齐、纠错。

## 一、工作方式（重要）

1. **先写骨架再边核边填**：开工第一步，就把 JSON 骨架（所有 id、所有字段、已有的种子事实）写进输出文件；
   之后每核完一座装置（或一组课题）就把文件写回磁盘一次。中途被打断时，磁盘上的文件必须是合法 JSON、内容尽量多。
2. **每条事实尽量两个来源**，一手或官方来源优先（实验室官网与官方史、项目设计报告、得主的诺奖演讲、
   瑞典皇家科学院 kva.se、NASA / CERN / NSF / DOE 页面、期刊论文、当事人著作），其次是 AIP、APS、Physics Today、
   CERN Courier、Symmetry、Britannica、大学新闻稿。**维基百科只作辅助**，只有维基一个来源的事实，置信度不得高于「中」。
3. **置信度**：高 = 一手或官方来源明写，且至少两个独立来源一致；中 = 只有一个可靠来源，或来源之间口径略有出入；
   低 = 只有二手转述、回忆录孤证或维基。**来源对不上时并列写出各家说法**（放进 `disputes`），不要替读者挑一个。
4. **数字要写口径**：造价是哪一年的钱、什么币种、含不含运行费；质量是总量还是有效体积；人数是论文作者数还是合作组成员数；
   尺寸是直径、周长还是臂长；日期精确到能查到的最细一级。
5. **逸闻只收有出处的**：当事人自述、诺奖演讲、实验室官方史、有名有姓的著作。查不到出处的写 `kind: "传说"`，或者不收。
6. **不许编**。查不到就写进 `todo`。宁缺毋滥。
7. **不要大段照抄**来源原文。颁奖词等短引文照录原文并给中译；其余一律用自己的话写。
8. 工具：WebSearch（只返回标题和链接，要看内容得用 WebFetch 打开）；WebFetch。如果它们不在工具列表里，先用 ToolSearch 加载
   （`select:WebSearch,WebFetch`）。
   - **nobelprize.org 在这个环境里返回 403，不要绕**；颁奖词与背景材料改用 kva.se、Britannica、AIP、实验室官网等。
   - 维基百科 / 维基共享资源等 Wikimedia 域名可能返回「cache-only, cannot be fetched」，**同样不要绕**，换别的来源。
   - 任何域名只要 WebFetch 报错或被拒，**一律不许用 curl、wget、python 等别的办法去抓网页**，换来源即可；这是硬规矩。
   - 如果 WebFetch 卡在等待授权或频繁超时，就退回 WebSearch 的标题信息，并把相应事实的置信度降一级、在 `notes` 里说明。
9. 控制篇幅和时间：每座「装置」大约 8–15 次网页抓取即可，够把关键数字核实两遍就停；候补席每条 1–3 次。
   不要追求穷尽，把时间花在数字、日期、人名和「待核」项上。
10. 完成后，你的最后一条回复只需要：输出文件路径、每座装置（或每组课题）一行的完成情况、`disputes` 和 `todo` 里最要紧的几条、
    以及你发现的种子事实里的错误（逐条列出「原写法 → 应为」）。不要把 JSON 全文贴回来。

## 二、中文文案的写法（所有中文字段都按这个写，编辑还会统稿）

- 平实、具体、先给数字。短句。像一位懂行的工程师在给同事讲，不像宣传稿。
- 不用这些套话：「不是……而是……」「值得一提的是」「可以说」「堪称」「令人惊叹」「毫不夸张」「众所周知」「里程碑式」「划时代」。
  不用反问句，不用感叹号，不堆形容词，不写排比。不要每段结尾来一句总结或升华。
- 人名：首次出现写「中文通行译名（英文原名）」，之后只写中文；没有通行译名的直接用英文原名，不要硬译。
- 数字用阿拉伯数字，四位以上加千分位逗号；单位用「米 / 公里 / 吨 / 升 / K / 美元」等，数字与单位之间空一格或不空保持一致（统一写「4 公里」「1.9 K」）。
- 对没有得奖的关键贡献者，措辞中性，只陈述事实，不替谁鸣不平。
- 「工程思维」（`lesson`）必须能指回本卡里有出处的具体做法；不要写成励志格言。
