# 第 7 题「冬天的门槛：不同纬度与气候下，各文明为什么在同一个季节祭亡灵、点灯火」· 研究员共用简报

你是四路研究员之一，为 tianjie.me「一周一题」第 7 题出底稿。页面是一张「世界地图 + 纬度阶梯 + 年轮」的滚动长页：序章「这十天」（10/31 万圣节 → 11/9 寒衣节，七个节日逐日点亮）、第 2 章「门槛：为什么是这个季节」（各文明节日的来历，地图 + 年轮）、第 3 章「同与异」（按纬度 / 气候 / 农事 / 历法 / 传播比较）、第 4 章「三件事」（请亡灵回家 · 把夜点亮 · 吃一顿）、两面动手墙（纬度与门槛、年轮）、三个小工具（算日子 / 同与异对照 / 看点清单）。读者是中文读者，正文中文。

站长天杰的原话（本题的需求边界）：「不同文明，按经纬度，气候，地理条件差异形成的各种相似时间的节日的异同分析」。所以每个节日都要答四个问题：**它落在哪个纬度、什么气候带？那时当地在收什么、怕什么（收成 / 牲口 / 雨季旱季 / 霜 / 长夜）？日子是怎么定的（固定日 / 月亮 / 太阳 / 规则）？它是本土长出来的，还是随宗教日历、移民、商业搬来的？**

## 铁律
1. **先写骨架、边核边填**：开工 10 分钟内先把你负责的全部节点按下面的 JSON 结构写进输出文件（字段可先空），之后每核完 1–2 个节点就覆盖写一次文件（用 Write 工具整份写，或用 python3 -I 改 JSON）。最后一条回复只报：文件路径、节点数、用了多少次搜索、哪些没核到。不要把内容贴在回复里。
2. **搜索预算 ≤25 次 WebSearch**（全会话共用额度 200 次，已用去一部分）。WebSearch 本次只返回链接不带摘要，所以要靠 WebFetch 打开页面核；WebFetch 只能打开「搜索结果里出现过的网址」或你从已打开页面里拿到的链接——凭记忆输入的网址可能停在审批上，遇到就换一个搜索词把它搜出来再开，不要用 curl 去抓网页（curl 只用来下载数据文件）。维基百科只作线索与辅助，关键年份、引文、数字要再找一个一手或权威来源（原典、官方机构、政府公告、权威专著、博物馆 / 大学页面、气象部门）。
3. **每个数字、年份、人名、引文都要有来源**；`confidence` 写 高 / 中 / 低：高 = 一手或两个独立权威来源一致；中 = 只有一个权威来源或权威来源间小有出入；低 = 只有维基 / 二手转述 / 通行说法。
4. **分歧并列**：起源说法不一（Samhain 是不是凯尔特新年、诸圣节定日的教宗与年份、trick-or-treat 的最早出处、亡灵节的阿兹特克连续性、Catrina 命名、七五三起源）写在 `dispute` 字段里，两说各给来源，不下结论。
5. **口径写清楚**：日期规则写成可算的形式（「农历十月初一」「amanta 历阿湿缚庾阇月（Ashvina）的朔日 amavasya，以日落时的 tithi 为准」「太阳黄经 225°」「泰历十二月望」）；气候数据写明口径（「印度气象局西南季风从西北印度撤退的正常日期 9 月 17 日、全国撤完 10 月 15 日」这种）。
6. 涉及民族、宗教、政治的史实（凯尔特 / 天主教 / 印度教 / 耆那 / 锡克 / 佛教 / 道教 / 阿兹特克与殖民）只用史料与官方 / 学术口径，措辞中性，不评论习俗，不做旅游推荐。
7. 页面上不会出现任何「待核」「无法核对」「本路」这类编辑用语——没核到的写在 `unverified` 列表里，不写进 `text` / `why` 字段。
8. 打不开的站点不要反复试：维基共享资源文件页多半打不开；nyrr.org、congress.gov 拒绝抓取；遇到 403 / 超时换来源。
9. **「气候决定节日」不能写成决定论**：只写「相关」与「门槛」——当地的收成 / 雨季 / 霜期和节日日期的关系，用数据说话；反例（搬到南半球春天里的节日、钉死在公历上的节日）如实写。

## 全页共用口径（请在各自范围内核对，不一致处写 dispute）
- 2026 年日期：万圣节 10/31（六）；诸圣节 11/1、诸灵节 11/2；篝火夜 11/5；立冬 11/7 17:52（北京时间，国立天文台暦要項 18:52 JST）；排灯节 11/8（印度使馆假日表）；寒衣节 = 农历十月初一 = 11/9（朔 11/9 15:02 北京时间）；圣马丁节 11/11；七五三 11/15；下元节 = 十月十五 = 11/23；水灯节正日按泰历十二月望推算 11/24（待核）；感恩节 11/26；墨西哥城亡灵节大游行 10/31 14:00（Reforma → Zócalo）。
